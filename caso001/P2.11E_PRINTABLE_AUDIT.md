# CASO 001 · P2.11E — AUDITORÍA DE IMPRIMIBLES

Estado: AUDITORÍA CERRADA · ESTÁNDAR P2 DEFINIDO · GENERADOR VISUAL PENDIENTE

## 1. Objetivo

Auditar el material imprimible heredado de V1 y definir qué puede conservarse, qué debe retirarse y cómo deben construirse los imprimibles de P2 sin crear una segunda fuente de verdad paralela al juego digital.

Principio rector:

> Una sola fuente de verdad: `manifest.json` + Paquete de Crimen seleccionado. El digital y el imprimible derivan de la misma información estructurada.

La raíz publicada de producción no se modifica en esta fase.

---

## 2. Resultado de auditoría V1

### 2.1 Material reutilizable

Se conserva como base visual/conceptual:

- guía de 6 PERSONAS;
- guía de 6 ESCENAS/LUGARES;
- guía de 6 OBJETOS;
- estética de expediente/investigación;
- códigos visibles de referencia que no codifiquen la solución;
- posibilidad de salida COLOR y ECO/B&N.

La biblioteca P2 mantiene exactamente el universo estable:

**Personas**
- SANTIAGO · Santiago
- CLARA · Clara
- VERA · Vera
- MATEO · Mateo
- INES · Inés
- TOMAS · Tomás

**Escenas**
- L1 · Sala de estar
- L2 · Cocina
- L3 · Estudio
- L4 · Dormitorio
- L5 · Jardín / exterior
- L6 · Pasillo / acceso

**Objetos**
- O1 · Arma
- O2 · Cuaderno
- O3 · Celular
- O4 · Llave
- O5 · Memoria USB
- O6 · Pañuelo

### 2.2 Material V1 DEPRECADO para P2

No debe migrarse a P2:

- regla `Persona + Lugar`, `Lugar + Objeto`, `Persona + Objeto`;
- sistema `Pista prometedora / Pista parcial / Línea débil`;
- tablero tipo hit/miss o Mastermind;
- acusación final limitada a Persona + Lugar + Objeto;
- cualquier texto que enseñe al jugador a resolver el caso por descarte matricial;
- cualquier imprimible que contradiga el revelado narrativo E1 → E2 → E3.

Motivo: P2 no genera una combinación aleatoria para luego descartarla. Cada partida nace de un Paquete de Crimen coherente con verdad previa, motivo, cronología, contradicción, evidencias y reconstrucción.

---

## 3. Auditoría de los 12 Paquetes de Crimen

El QA P2.11D ya verificó que 12/12 paquetes contienen un recorrido E1 → E2 → E3 jugable y que los testimonios necesarios poseen canal humano/NPC cuando corresponde.

Para imprimibles, esto implica:

- 12/12 tienen evidencia estructurada utilizable como fuente;
- 12/12 tienen etapas 1, 2 y 3;
- 12/12 pueden producir documentos sin inventar una segunda solución;
- testimonios privados pueden representarse como ficha privada si el personaje es humano;
- `npcFallback` permite producir declaración de expediente cuando ese personaje es NPC;
- `motive`, `criticalEvent`, `mechanism`, `postCrimeAction`, `contradiction` y `epilogue` existen para el cierre, pero NO forman parte del pack imprimible previo al reveal.

### Limitación actual

La evidencia es semánticamente imprimible, pero todavía no toda tiene una dirección artística específica. Por ejemplo, un mensaje, una cámara, un recibo, un registro de acceso o una comparación de fibras deberían verse distintos aunque todos provengan de `evidence.text`.

Esto no requiere duplicar contenido. Se resuelve con plantillas visuales por `evidence.type` y, cuando haga falta, metadatos de presentación que no cambien el hecho narrativo.

---

## 4. Kit Base P2 congelado

El kit base de una partida P2 tendrá **8 páginas A4** reutilizables y seguras:

1. **Portada / Expediente del caso** — Caso 001, prólogo y arranque sin spoilers.
2. **Personas** — 6 sospechosos/personajes.
3. **Escenas** — 6 espacios de investigación.
4. **Objetos** — 6 objetos clave.
5. **Hoja de investigación P2** — Persona + Escena + Objeto + Motivo, con hechos, contradicciones, coartadas e hipótesis.
6. **Línea de tiempo** — franja cronológica para reconstrucción.
7. **Mapa de relaciones** — vínculos, deuda/conflicto, coartada y contradicción.
8. **Acusación final** — Persona + Escena + Objeto + Motivo/Hipótesis causal + reconstrucción breve.

Estas 8 páginas no contienen la identidad del responsable ni datos exclusivos de un Crime Pack antes de que la partida lo haya seleccionado.

---

## 5. Capa dinámica de evidencias

Las evidencias específicas NO se mantienen en una biblioteca manual separada.

Se derivan de:

`room → pack seleccionado → evidence[] → stage → canal de entrega`

### Stage 1 · Apertura

Solo material liberable en E1.

- evidencia pública E1 → imprimible pública E1;
- evidencia privada E1 → solo para su destinatario;
- nunca se imprime anticipadamente E2/E3 en un pack abierto sobre la mesa.

### Stage 2 · Fractura

Misma regla para `stage:2`.

### Stage 3 · Pivote

Misma regla para `stage:3`.

### Testimonio humano/NPC

Si una evidencia testimonial es privada:

- personaje humano → ficha privada para ese jugador usando `evidence.text`;
- personaje NPC → declaración de expediente usando `npcFallback`.

Nunca se imprime una declaración privada del humano como evidencia pública solo por conveniencia de producción.

---

## 6. Plantillas por tipo de evidencia

P2 usa seis familias canónicas. Cada familia recibe una plantilla visual por defecto:

| `evidence.type` | Plantilla de impresión |
|---|---|
| `temporal` | registro / cronología / bitácora |
| `testimonial` | declaración / entrevista |
| `physical` | ficha pericial / evidencia física |
| `digital` | captura / registro digital / dispositivo |
| `access` | acceso / llave / puerta / registro de ingreso |
| `motivational` | documento / borrador / factura / correspondencia |

El título y la apariencia pueden variar. El hecho narrativo deriva siempre de `evidence.text` o `npcFallback`.

---

## 7. Solución y spoilers

### Prohibido antes del reveal

No incluir en PDF, HTML imprimible, nombre de archivo, QR visible ni metadato público:

- `killer`;
- solución verdadera Persona + Escena + Objeto;
- `truthSummary`;
- `criticalEvent` completo si revela identidad;
- `mechanism` cuando resuelve el caso;
- `postCrimeAction`;
- `centralLie` atribuida explícitamente si funciona como solución;
- `epilogue.reconstruction`;
- `epilogue.closing`;
- `redHerrings[].resolution`.

### Después del reveal

Puede ofrecerse una hoja final opcional de resolución/reconstrucción. Debe generarse o habilitarse únicamente cuando la sala esté finalizada.

---

## 8. Salidas oficiales

Todo imprimible P2 tendrá dos variantes coordinadas desde el mismo master:

### COLOR
- estética completa Expedientes;
- fotografías y sellos;
- fondos controlados para no destruir legibilidad.

### ECO / B&N
- fondo blanco;
- contraste alto;
- tramas y líneas en lugar de depender de color;
- fotografías convertidas para impresión doméstica;
- consumo de tinta reducido.

No se mantiene contenido distinto entre COLOR y ECO.

---

## 9. Formato físico maestro

- Papel: A4, 210 × 297 mm.
- Orientación por defecto: vertical.
- Margen seguro mínimo: 10 mm; objetivo: 12 mm.
- Sin sangrado obligatorio para impresión doméstica.
- Raster de referencia: 300 dpi cuando se pre-rendericen imágenes.
- Texto cuerpo recomendado: 9.5 pt mínimo; objetivo 10–11 pt.
- Contraste: legible en escala de grises.
- Tarjetas: máximo 6 por A4 cuando se use formato tipo ficha; preferencia 2 columnas × 3 filas.
- Códigos/IDs nunca deben ser la única forma de reconocer un elemento.

---

## 10. Reglas de generación

1. El generador carga `manifest.json`.
2. Renderiza Kit Base con IDs canónicos.
3. Una vez que existe una sala y un Paquete de Crimen seleccionado, el servidor determina qué evidencia puede imprimirse.
4. El cliente recibe solo el material que ya tiene derecho a conocer.
5. El cliente no recibe el JSON completo del pack para fabricar un PDF.
6. El PDF/HTML imprimible no debe convertirse en una vía lateral para leer E2/E3 o la solución antes de tiempo.
7. El Modo Impostor no altera evidencia oficial.
8. Las teorías del jugador pueden escribirse libremente en hojas de trabajo, pero nunca modifican el expediente oficial.

---

## 11. Riesgo de seguridad actual

Los Crime Packs P2 continúan temporalmente en el repositorio público durante la integración. Un jugador técnico podría buscarlos fuera de la interfaz.

Por lo tanto:

- el estándar de imprimibles se define ahora;
- los packs dinámicos NO se consideran seguros para Release Candidate mientras la fuente maestra siga públicamente accesible;
- antes de RC los packs deben moverse a una fuente privada server-side, como ya está identificado en P2.12/P2.13.

---

## 12. Gate QA de un imprimible P2

Una salida se aprueba solo si:

- usa IDs canónicos;
- coincide con el contenido digital;
- no contiene reglas V1 de pares/hit-miss;
- distingue Persona / Escena / Objeto / Motivo;
- no libera etapas futuras;
- respeta privado vs público;
- aplica `npcFallback` cuando corresponde;
- no contiene solución antes del reveal;
- se entiende impresa en B&N;
- no corta texto en A4;
- no depende de conexión para que el usuario vea una hoja ya descargada;
- el archivo indica Caso 001 y versión del estándar, pero no codifica secretamente la solución.
