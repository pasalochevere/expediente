# CASO 001 · P2.11F — GENERADOR IMPRIMIBLE P2 V1

Estado: IMPLEMENTADO EN RAMA SEGURA · QA VISUAL/FÍSICA PENDIENTE

## Objetivo

Construir un generador A4 real para Caso 001 P2 que use el estándar P2.11E y derive las evidencias de la misma fuente narrativa que el juego.

Archivo:

- `printables/generator-p2.html`

La raíz productiva `index.html` no se modifica.

## 1. Kit Base implementado

El generador produce ocho páginas A4:

1. BASE-01 · Expediente / prólogo común P2.
2. BASE-02 · Personas.
3. BASE-03 · Escenas.
4. BASE-04 · Objetos.
5. BASE-05 · Hoja de investigación.
6. BASE-06 · Línea de tiempo.
7. BASE-07 · Mapa de relaciones.
8. BASE-08 · Acusación final.

La acusación captura:

- Persona responsable;
- Escena clave;
- Objeto clave;
- Motivo / hipótesis causal;
- reconstrucción breve.

No se usa la mecánica V1 de parejas ni Prometedora/Parcial/Débil.

## 2. Prólogo común corregido

El prólogo imprimible V1 no se reutiliza porque fijaba una cronología propia —apagón, hora crítica y desaparición— incompatible con los 12 Crime Packs P2.

P2.11F usa una apertura común que solo establece:

- Esteban Valdés convocó a las seis personas;
- existían tensiones previas;
- Esteban murió dentro de la propiedad antes de terminar la noche;
- la verdad debe reconstruirse cruzando personas, escenas, objetos, tiempos y contradicciones.

No fija hora crítica, mecanismo, escena verdadera, objeto verdadero ni responsable.

## 3. Evidencia dinámica

El generador puede cargar `C001-01` … `C001-12` desde `../packs/` cuando se sirve desde el repositorio.

Para uso local permite cargar un JSON manualmente.

Tipos renderizados:

- temporal → REGISTRO TEMPORAL;
- testimonial → DECLARACIÓN;
- physical → FICHA PERICIAL;
- digital → EVIDENCIA DIGITAL;
- access → CONTROL DE ACCESO;
- motivational → DOCUMENTO CONTEXTUAL.

Se renderizan dos documentos de evidencia por A4.

## 4. Liberación por etapa y canal

Selector de etapa:

- E1;
- E2;
- E3.

Selector de canal:

- CASEFILE — evidencia pública + fallbacks NPC;
- PRIVATE::SANTIAGO;
- PRIVATE::CLARA;
- PRIVATE::VERA;
- PRIVATE::MATEO;
- PRIVATE::INES;
- PRIVATE::TOMAS.

El operador también indica qué personajes son humanos.

Regla:

- `public:true` se muestra en CASEFILE cuando `stage <= etapa actual`;
- privada + personaje humano se muestra solo en el canal privado de ese personaje;
- privada + personaje NPC se convierte en `npcFallback` dentro de CASEFILE;
- nunca aparecen simultáneamente la versión privada y el fallback NPC.

## 5. Seguridad narrativa

La salida de jugador usa únicamente:

- `evidence.text`;
- `npcFallback` cuando corresponde.

El generador no consulta para render de jugador:

- `deduction`;
- `truthSummary`;
- `criticalEvent`;
- `mechanism`;
- `postCrimeAction`;
- `centralLie`;
- `redHerrings[].resolution`;
- `epilogue`.

No existe página de solución en P2.11F.

## 6. COLOR / ECO

Un único DOM y una única fuente de contenido producen:

- COLOR;
- ECO / B&N.

ECO cambia tratamiento visual pero no contenido.

## 7. Impresión

- A4 210 × 297 mm;
- margen visual interno 12 mm;
- `@page size: A4; margin: 0`;
- cada `.page` corta como una hoja independiente;
- salida mediante `window.print()` para imprimir o guardar como PDF.

## 8. Assets

Las fotografías V1 están embebidas como Base64 dentro del `index.html` histórico y no se duplicaron en P2.11F.

P2.11F usa una representación dossier liviana mediante iniciales/símbolos. Esto evita:

- duplicar cientos de KB de Base64;
- crear una dependencia frágil con el V1;
- convertir el generador nuevo en otra copia del monolito productivo.

La capa de arte/fotografía reutilizable queda como mejora visual posterior, sin modificar la lógica de contenido.

## 9. QA incorporado

El generador valida al cargar un pack:

- `id` presente;
- seis o más evidencias;
- stage 1/2/3;
- tipo de evidencia conocido;
- privada testimonial con `sourceCharacter` debe tener `npcFallback`.

Muestra en pantalla el número de evidencias imprimibles del canal/etapa actual.
